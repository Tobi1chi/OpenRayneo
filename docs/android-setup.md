# 手机配置与 Codex 连接

当前版本：0.4.0-dev。导航改为跟随手机高德 App 的通知，已移除高德 SDK、Key 配置和定位权限。手机独立模型及电脑 Codex 配置保留。

0.2.0-dev 曾验证 USB Codex 对话、SDK 搜索和原地导航显示，随后用户报告导航内容触发眼镜自动滚动，并要求改用高德 App 通知。0.2.1-dev 根据真实高德通知实现接收与指令提取，并补齐 Mac 导航显示流程；用户已确认通知导航“显示正常，不再滚动”。实时提示页仍待单独验收。详见 [高德通知导航](android-notifications.md)。

## 安装及配置

安装 `OpenRayneo-0.4.0-dev.apk`，允许附近设备权限。在“设置 → 导入本地配置文件”选择提供的 JSON，导入电脑连接参数；该文件含连接凭据，导入后删除手机“下载”中的副本。“保存配置”使用 Android Keystore 加密保存在应用私有目录，凭据不进入源码或应用诊断日志。

“设备”页扫描并连接眼镜，保持 BLE 诊断选项关闭。可选择允许后台状态通知；前台服务在页面退出后持有连接，并在非主动断连时最多尝试三次扫描重连，不自动删除配对。遇到系统配对窗口需要确认。

## 高德 App 通知导航

1. 在“导航”页打开系统的通知使用权设置，允许 OpenRayneo；应用代码只处理高德的导航通知。
2. 连接眼镜，然后在高德 App 中选目的地、选择步行／骑行并开始导航，回到桌面让高德更新导航通知。
3. 回到 OpenRayneo 确认跟随的通知。首次发现实测导航频道中含明确动作和距离的通知时会自动选中；也可手动选择。只有“正在导航”的通知无法提供转向。
4. 眼镜恢复固定 20×5 网格，大箭头、距离、动作与底行 8 格路名。启动字幕音频后配置布局，手机顶部显示单声道音量及解码时长；这条组合路径仍待真机确认。无法识别、通知移除或读取权限断开时清除旧指令，改为简短状态卡。
5. “停止眼镜跟随”关闭当前导航显示及其音频会话，保留蓝牙连接，不再自动打开实时提示；不会停止高德 App 中的路线。当前如果显示的是回答，停止跟随只取消后续返回导航，不关闭回答。重新选择通知或点击“恢复眼镜导航显示”打开导航；设备页“打开实时提示与收音”明确打开实时提示。

不需要在 OpenRayneo 配置高德 Key 或精确定位权限。此前已经申请的 Key 不再被本应用使用。通知格式和更新频率依赖高德与系统版本，不能把通知方式等同于所有导航 SDK 数据。

## 手机 Agent

在设置中填写兼容 Chat Completions 的 HTTPS 服务地址、模型名和 API Key。地址可以是以 `/v1` 等版本路径结尾的基础地址，也可以直接以 `/chat/completions` 结尾；不支持把密钥放进 URL。不预填供应商、模型或假凭据。

模型需支持 `tools`／`tool_calls`。实现支持 SSE 流式文本和函数参数片段，也处理非流式响应；最多连续执行六轮。当前工具为导航通知跟随状态、停止眼镜跟随、眼镜通知。目的地选择和启动路线在高德 App 中完成。会话历史目前保留在服务内存中，进程退出后不恢复。取消停止后续模型请求，已经执行的工具操作会保留。模型服务兼容性需用用户实际选择的接口验证。

“手机系统语音输入”依赖手机安装的识别服务，目前未接入眼镜音频。0.3.1-dev 导航恢复字幕固定网格，在同一字幕 SID 内接收 type 4 音频并按单声道解码；问答使用实时提示和双声道。页面模式切换会停止旧音频会话并启动新会话，导航内容更新不重开会话。“结束眼镜回答”回到进入回答时记录的导航、实时提示或空闲；导航已停止时回空闲。导航中回答写出后约 12 秒恢复导航；眼镜退出、用户暂停或切换后旧计时器失效。设备页提供“暂停眼镜显示与收音”“打开实时提示与收音”和“重启音频解码（保持页面）”。后者只重启本地解码器，不要求固件重新开麦。停止导航后新提交的任务可以显示回答；停止前仍在处理的旧回答不会抢回页面。已让出给眼镜外部页面时，需要主动选择功能恢复。完整规则见 [眼镜协调器](android-state-machine.md)。

眼镜音频使用系统 MediaCodec 解码为 48 kHz PCM16，只在内存中计算音量，不保存、不上传、不自动识别。ASR 工作已按用户要求暂停：本机小米 AsrService 自行启动手机麦克风，没有实现外部 PCM 输入；Android 标准 `EXTRA_AUDIO_SOURCE` 接口需要引擎主动支持。本机 Google 代码中存在该接口，但旧 GoogleRecognitionService 未启用，系统拒绝 ADB 启用，尚未做识别实测；没有改变系统默认识别服务，也未新增 ASR 权限或依赖。

## 电脑 Codex：USB 联调

电脑安装并配置 Codex CLI，然后在仓库根目录运行：

```sh
uv run python scripts/phone-codex.py \
  --workspace /absolute/path/to/workspace \
  --phone-config analysis/OpenRayneo-setup.json
```

程序生成或复用 `~/.config/openrayneo/phone-token`，令牌和导入文件权限为 `0600`。控制台不会打印令牌。文件中的电脑目录限制了客户端默认任务位置，但不应将其理解为完整的安全隔离策略；真正的文件／命令权限由 Codex sandbox 和审批控制。App 请求 `workspace-write`、`on-request`，审批在手机上显示。

服务只监听 `127.0.0.1:4500`，使用 bearer token 认证。它继承电脑 CLI 当前模型及登录配置；不要把它等同于桌面 App 的每个聊天或登录状态。本次验证时 CLI 使用的是已配置 API Key 模式。

保持电脑程序运行，USB 连接手机并授权调试，在另一终端执行：

```sh
adb reverse tcp:4500 tcp:4500
adb push analysis/OpenRayneo-setup.json /sdcard/Download/OpenRayneo-setup.json
```

手机导入文件后，在“电脑”页连接 Codex 并发送任务。会话 ID 加密保存在手机；重新连接尝试恢复同一会话，不自动重发上一条任务。支持流式回答、一次性命令／文件审批、工具提问及取消。未知服务端请求返回明确错误，不自动批准。新电脑会话与本聊天独立。

停止电脑程序用 Ctrl+C；移除 USB 转发可用 `adb reverse --remove tcp:4500`。如果配置文件外泄，停止服务后通过正常本地文件操作替换 token 文件，再生成并重新导入新配置；旧 token 不再用于新服务。

依据：[Codex App Server 官方文档](https://learn.chatgpt.com/docs/app-server)。接口已按本机 `codex-cli 0.162.0-alpha.17.2` 生成的 schema 核对。官方仍将 App Server WebSocket 标记为实验性；升级 CLI 后需回归初始化、会话、审批和取消。

## 无线与外出连接

客户端支持 `wss://`，并使用系统证书验证。当前脚本仅启动本机 WebSocket；无线使用还需配置受信任的 TLS 入口或加密隧道，保留 bearer token 认证。不要把手机的 `127.0.0.1` 当成电脑局域网地址；USB 断开后反向转发也不能作为外出连接。

同一 Wi-Fi 和蜂窝网访问仍待实际部署、验证，不能仅凭客户端支持 WSS 宣称互联已完成。电脑必须在线；休眠或离线时手机导航和已配置的手机模型仍可独立使用。导航、眼镜麦克风并行显示及后台长时间运行仍需后续验收。
